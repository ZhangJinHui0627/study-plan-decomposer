# 大创答辩评委问答提示与技术防御（团队内部备考版）

> 💡 **内部使用提示**：本文件供张锦慧及团队成员答辩前备考准备，包含评委可能提出的刁钻问题应对策略与口语化表达指南。

---

## ❓ 热门考问 1：为什么不用现在流行的大模型直接解析，而要用正则表达式？

- **评委可能的提问方式**：“现在大模型（LLM）这么火，直接调用 API 提取不是更方便吗？为什么你们还退回去用正则表达式这种传统技术？”
- **内部应对逻辑**：
  1. **隐私安全**：学生的每日作息、学习弱项上传到云端大模型有隐私泄露隐患，本地正则 100% 离线，数据只存在手机 SQLite 数据库。
  2. **响应速度与资源消耗**：大模型 API 响应需要 1~3 秒，且需要网络和 Token 成本；正则解析只需 20ms，零流量费，APK 只有 5.8MB。
  3. **结果可控性**：大模型存在“幻觉”，可能把任务量算错；正则表达式规则明确，输出 100% 稳定可预测。

---

## ❓ 热门考问 2：正则表达式遇到口语化、格式多样的文本，怎么保证 90% 以上的准确率？

- **评委可能的提问方式**：“学生的输入千奇百怪，正则表达式是很死板的，你们怎么做到 93.4% 准确率的？”
- **内部应对逻辑**：
  1. **前端预处理清洗 (`TextPreprocessor`)**：在匹配前先做过滤，把全角转半角，把“请帮我”、“打算”等客套话删掉，规范时间单位（小时->分钟）。
  2. **分层组合匹配**：不写一个巨大的复杂正则，而是拆分为时间正则、时长正则、页码正则、学科字典四大独立模块，各自抽取后拼接。
  3. **内置扩展词库 (`SubjectRulesView`)**：支持用户和系统动态补充学科专业词汇，覆盖度越来越高。
